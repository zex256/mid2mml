# mid2mmlGUI

Windows用のMIDI → ppmck MML変換画面です。C# WinFormsで作成し、同じフォルダにある mid2mml.exe を外部プロセスとして呼び出します。
生成したMMLをppmckでNSFへ変換し、関連付けプレーヤーで開くこともできます。

## 使い方

1. 「入力MIDIファイル」の参照ボタンから .mid または .smf を選びます。入力欄への1ファイルのドラッグ＆ドロップでも指定できます。
2. 必要に応じて変換オプションを変更します。「実行コマンド」は確認用です。
3. 「MMLへ変換」を押します。変換中の出力とエラーは下部に表示されます。
4. 正常終了後、生成した .mml をWindowsで関連付けられたアプリで開きます。
5. NSFを生成する場合は、MMLの編集を保存してから「ppmckのbin」を指定し（初期値 `D:\mck\bin`）、「NSFへ変換」を押します。
6. 入力MIDIと同じフォルダの `<MIDI名>.nsf` を生成し、Windowsで関連付けられたNSFプレーヤーで開きます。

出力先は入力MIDIと同じフォルダです。同名の .mml と中間MIDIは上書きされます。関連付けアプリを起動できなくても、変換結果は残ります。

MML・NSF変換開始時に、入力MIDI・変換プログラム・ppmckのbinのパスと全オプションを `%LOCALAPPDATA%\mid2mmlGUI\settings.json` に保存します。次回起動時に復元し、初回や設定ファイルが不正な場合はデザイナーの初期値を使います。保存できない場合はログに表示し、変換は続行します。「既定値に戻す」はオプションのみを戻し、次の変換時に保存されます。ファイルの再配置・削除があってもパスは復元され、変換時に存在を確認します。

## NSFへの変換

ppmckは別途必要です。指定したbinフォルダには `ppmckc.exe` と `nesasm.exe`、その親フォルダには `nes_include\ppmck.asm` とドライバー一式を配置してください。NSFプレーヤーはWindowsで `.nsf` に関連付けてください。関連付けがない場合も生成したNSFは残ります。

「NSFへ変換」は、選択中のMIDIと同名の保存済みMMLを使用します。MIDIからMMLを自動で再生成しないため、MMLの編集内容を保存してから実行してください。

専用の一時フォルダで `ppmckc -i <MMLの絶対パス> song.h` を実行して `effect.h` と曲データを生成し、続けて `nesasm -s -raw ppmck.asm` を実行します。`song.h` は中間生成物を入力フォルダに散在させないための明示的な出力名です。複数曲用の `-u` は使いません。

子プロセスだけに `PPMCK_BASEDIR` と `NES_INCLUDE` を設定します。DPCMは入力フォルダ、ppmckの `songs`、それぞれの `dmc` フォルダから探します。日本語を含むppmckのログはShift-JISとして表示します。生成物のNSFヘッダーを確認し、成功した場合だけ `<MIDI名>.nsf` を置き換えます。エラーや中止では既存のNSFを変更しません。一時生成物は終了時に削除します。

ピッチ最低変化量はセント単位です（100セント＝1半音、既定値5セント）。RPNを反映したMIDI音程偏差の最大値－最小値を、基準の0セントを含めて判定します。音源のレジスタ値による判定は行いません。

LFO(MPコマンド)使用（-l）は既定で有効です。チェックを外すと、@MP定義とMPコマンドを出力しません。
MIDIピッチベンド由来のピッチエンベロープには影響しません。LFOの選択も保存・復元します。

## 開発と発行

.NET 10 SDKと、同じソリューションの CLI プロジェクトでビルドした mid2mml.exe が必要です。
Visual Studioではルートの mid2mml.sln を開くと、CLIを先にビルドできます。

GUIプロジェクトを単独でビルドする場合は、先にCLIの対応する構成をビルドし、
GUIフォルダで以下を実行します。発行前にはCLIのRelease構成が必要です。

    dotnet build
    dotnet publish -c Release

発行先の publish フォルダには、mid2mmlGUI.exe と mid2mml.exe の2ファイルを配置します。GUIは自己完結型のwin-x64単一EXEで、利用者側に.NETのインストールは不要です。GUIのEXEは.NETランタイムを含むため、ファイルサイズは大きくなります。

CLIの場所が異なる場合は、発行時に MSBuild プロパティ Mid2mmlCliSource へそのEXEのフルパスを指定できます。開発時のGUI起動でも「変換プログラム」欄から任意の mid2mml.exe を選択できます。

## 画面の項目

画面から -c、-r、-vm、-vt、-pm、-pt、-n、-m、-d を指定できます。チャンネル割当順の既定値は `ABCMNOabFXYZPQRSTUVWGHIJKL`、音符分解能の初期値はCLI・GUIともに `32` です。その他の既定値と許容範囲はCLIの ReadMe.txt に合わせています。音量モード0・1では -vt の入力欄を無効にしますが、その値は保持してCLIへ渡します。

引数はシェルを通さず ProcessStartInfo.ArgumentList に追加します。入力MIDIのフォルダを作業フォルダとしてCLIを起動し、UTF-8の標準出力・標準エラーを順次表示します。中止ボタンを押すと変換プロセスを終了します。

## GUI機能の検証

CLIのReleaseビルド後、リポジトリ直下で以下を実行します。

    dotnet run --project tests/GUI/GuiVerification.csproj -c Release

実フォームのドラッグ＆ドロップイベント、全入力・選択値の保存と復元、不正設定・保存失敗の扱いを確認します。さらに `D:\mck\bin` の実際のppmckツールで、NSF生成、DPCM探索、日本語・空白のあるパス、失敗・中止時の既存NSF保護を確認します。テスト専用の一時フォルダへ保存し、利用者の設定ファイルは変更せず、プレーヤーも起動しません。
