mid2mml for ppmck
=================

公開先: https://github.com/zex256/mid2mml

概要
----

mid2mmlは、Standard MIDI File（SMF）をppmck向けのMMLへ変換する
コマンドラインツールです。

MIDIのノート、テンポ、拍子、マーカー、音色、音量、ピッチベンドなどを解析し、
ppmckで扱えるチャンネル、音色定義、音量エンベロープ、ピッチエンベロープへ
変換します。

対応する主な音源は次のとおりです。

  A、B       2A03 矩形波
  C          2A03 三角波
  D          2A03 ノイズ
  E          2A03 DPCM
  F          FDS  波形メモリ音源
  G～L       VRC7 FM音源
  M、N       VRC6 矩形波
  O          VRC6 鋸波
  P～W       N106 波形メモリ音源
  X～Z       FME7 矩形波
  a、b       MMC5 矩形波

使用環境
--------

制限：Windows 10 バージョン1903以前の場合、コマンドライン表示の多バイト文字が文字化けすることがあります。

実行方法
--------

  mid2mml.exe [オプション] <入力MIDIファイル>

例：

  mid2mml "D:\mck\songs\sample.mid"
  mid2mml -r32 -vm3 -d3 "sample.mid"
  mid2mml -c:ABCabMNOXYZPQRSTUVWGHIJKLF "sample.mid"

入力MIDIファイルは1ファイルだけ指定できます。パスに空白が含まれる場合は
二重引用符で囲んでください。

オプション名の英字は大文字・小文字を区別しません。ただし、-cで指定する
チャンネル文字は大文字・小文字を区別します。オプションと値の間に空白は
入れず、-r32や-vm3のように続けて指定してください。

コマンドラインオプション
------------------------

  -c:<チャンネル割当順>
      MIDIメロディートラックから割り当てるppmckのMMLチャンネルを順番に指定します。
      指定可能チャンネルは ABCFGHIJKLMNOPQRSTUVWXYZab です。
      DとEは、MIDIのパーカッション10チャンネルからの変換に使用するため指定できません。
      同じチャンネルを重複して指定することはできません。
      指定した文字数を超えるメロディートラックはMMLへ変換されません。
      既定値は ABCabMNOXYZPQRSTUVWGHIJKLF です。

  -r<音符分解能>
      変換する音符・休符の分解能を指定します、何分音符まで表現するかを指定します。
      指定可能な値は 4、8、16、32、64、128、256 です。
      大きい値ほど細かい分解能となり、繊細なタイミングを表現できる反面、
      音符の付点やタイ2が増え、記述量が多く読み難い譜面となります。
      イベント時刻は最も近い単位へ丸められます。
      既定値は 32 です。

  -vm<音量モード>
      音量の出力方法を指定します。
        0  固定音量
           チャンネル先頭でvコマンドを出力し、以降の音量変化は出力しません。
        1  可変音量
           音量が変化するたびにv+またはv-コマンドを出力します。
        2  音色別音量
           音色と音量に対応する@v定義を使用し、チャンネル先頭と音色変更後に
           選択します。音色が同じ間の音量変化には追従しません。
        3  音色別音量＋可変音量（既定値）
           音色と音量に対応する@v定義を使用し、音量が変化するたびに
           対応する定義へ切り替えます。

  -vt<音量定義数の間引き閾値>
      音量エンベロープ定義の数を間引き始める件数の閾値を指定します。
      これは音量エンベロープ定義が増え過ぎるのを抑制する為の機能です。
      （音量値そのものを制限するものではありません。）
      指定可能な値は0～65535、既定値は15です。
      0を指定すると最大限に間引く方向に働き、非常に大きい値を指定すると
      実質的に間引きを無効にします。
      登録数が閾値以上になったときに段階的に間引くため、最終的な登録数を
      指定値以下に制限する上限ではありません。
      この設定は、-vm2または-vm3で生成する@v定義にだけ影響します。

  -pm<ピッチ最大定義数>
      ピッチエンベロープを定義する最大数を指定します。
      これはピッチエンベロープ定義が増え過ぎるのを数で制限する為の機能です。
      指定可能な値は0～128、既定値は15です。
      上限へ達した後も登録済みの同一定義は再利用しますが、新しい定義は登録せず、
      その音符ではピッチエンベロープを無効にします。
      0を指定した場合、ピッチエンベロープを定義しません。

  -pt<ピッチ最低変化量閾値（セント）>
      MIDI側の音程変化幅をセント単位で指定します。100セント＝1半音です。
      RPNのベンド範囲を反映した音程偏差の最大値と最小値の差で判定します。
      基準音程の0セントも含めるため、発音開始時から一定のベンドも判定対象です。
      音源やノート番号によらず、変化幅がこの閾値未満なら定義しません。
      これは微細な変化では定義しないことにより、定義数を抑制するための機能です。
      （ピッチエンベロープ値の範囲を制限するものではありません。）
      指定可能な値は0～65535セント、既定値は50セントです。
      0を指定すると、変化量による登録除外を行いません。
      レジスタ範囲への制限は別に行い、整数化後のEPが全て0なら定義しません。
      旧版の-ptはレジスタ変化量でしたが、現在はセント単位です。

  -n<重複音符の切詰率(%)>
      同じMIDIトラックの音符が重複した場合、先の音符の末尾を切り詰めることにより、
      重複せずに後の音符を同じトラックへ収める動作をします。
      この切り詰める割合を0～100(%)で指定します。既定値は25です。
      この割合で切り詰めてもなお重複する場合は、切り詰めるのではなく、
      直後に新トラックを生成して、そちらに重複した後の音符を分離します。
      0を指定すると音符切り詰めは行わず、重複した音符を全て新トラックへ分離します。
      パーカッションチャンネルはこの設定の対象外です。
      重複音符により新トラックが生成されたかどうかは、
      中間MIDIファイルを出力していますので、そちらを確認して下さい。

  -m<打楽器チャンネル統合>
      MIDIのSysExにより（チャンネル10以外の）パーカッションに設定された
      トラックを、チャンネル10へ統合するかを指定します。
      指定可能な値は0/1です。0で統合せず、1で統合します。
      既定値は1です。

  -d<打楽器音源割当モード>
      MIDIパーカッション（チャンネル10）をppmck MMLのDチャンネル（ノイズ音源）と
      Eチャンネル（DPCM音源）のどちらへ割り当てるか指定します。
        1  全てノイズ音源
        2  全てDPCM音源
        3  ノート番号別の内部割当表によるノイズ音源とDPCM音源へ振り分け（既定値）
           これはシンバル系はノイズ音源、ドラム系やその他はDPCM音源に割り当てます。

  -l<LFO(MPコマンド)使用>
      ppmckのLFO（@MP<num>定義とMP<num>コマンド）を使用するか指定します。
        1  使用（既定値）
        0  不使用
      -l0ではLFO定義とコマンドを出力しません。
      MIDIピッチベンド由来のピッチエンベロープには影響しません。

  -t<曲冒頭の無音区間を切詰>
      MIDIの最初の音符より前にある無音区間を、拍子に基づく小節単位で切詰します。
        1  有効（既定値）
        0  無効
      -t0では曲冒頭の無音区間を維持します。小節未満の無音は有効時も残ります。
      中間MIDIはこの切詰処理より前に保存するため、-tの指定では変わりません。

生成されるファイル
------------------

入力ファイルが sample.mid の場合、同じフォルダーへ次の2ファイルを出力します。

  sample.mml
      ppmck向けのMMLです。曲情報、音源使用宣言、音色・音量・ピッチ定義、
      各チャンネルの演奏データを含みます。

  sample_.mid
      MML変換前の中間MIDIです。パーカッションの統合・分割、不要イベントの
      削除、重複音符の分割、テンポ・拍子・マーカーの展開などを反映しています。
      意図しないトラック分割や音符処理を確認するときに使用できます。

同名の出力ファイルが存在する場合は上書きされます。

変換処理の概要
--------------

1. MIDIファイルを読み込みます。
2. 必要に応じてパーカッションをチャンネル9へ統合します。
3. 不要なSysEx、未使用イベント、空トラックを整理します。
4. パーカッションをノイズ／DPCMトラックへ分割します。
5. 重複音符を調整し、テンポ・拍子・マーカーを各トラックへ展開します。
6. 確認用の中間MIDIを保存します。
7. -t1の場合のみ曲冒頭の無音区間を切詰します。分解能とイベント時刻は常にMML変換用に調整します。
8. ppmck向けMMLを生成します。

ビルド
------

必要な環境：

  ・Visual Studio C++ツールセット v145
  ・Windows 10 SDK
  ・C++17対応コンパイラ

リポジトリのルートにある mid2mml.sln をVisual Studioで開き、
Win32のDebugまたはRelease構成をビルドしてください。実行ファイルは
CLI\Debug\mid2mml.exe または CLI\Release\mid2mml.exe に生成されます。

Developer PowerShellからRelease版をビルドする例：

  MSBuild.exe .\mid2mml.sln /t:Rebuild /p:Configuration=Release /p:Platform=Win32

テスト
------

Release版をビルドした後、プロジェクトのルートで次を実行します。

  .\CLI\tests\Invoke-Tests.ps1 -Executable .\CLI\Release\mid2mml.exe

このスクリプトは、DPCMの回帰比較、各ドラムモードの変換、
コマンドラインオプション、MIDIテキストの文字コード変換を検証します。

主要ファイル
------------

  mid2mml.cpp
      コマンドライン解析と変換処理全体の制御。

  midi.cpp / midi.h
      SMFの読み書きとMIDIイベント・トラックの変換。

  mml.cpp / mml.h
      MIDIイベントの解釈とppmck向けMMLの生成。

  ToneDef.cpp / ToneDef.h
      General MIDI音色名、ドラム名、各拡張音源の音色・音量定義。

  text_encoding.cpp / text_encoding.h
      MIDIテキストの文字コード判定と出力文字列の変換。

  tests
      回帰テスト、文字コードテスト、基準出力。

フォルダー
----------

  dmc
      25.dmc～87.dmcは、MML生成時にDPCM音源データとして参照されます。
      ppmckを使用する場合は、これらのファイルを \mck\songs\dmc\ へコピーしてください。

注意事項
--------

ピッチベンドは半音単位の変化量から周波数比を計算し、ppmck標準ドライバの
音階表を基準に、各音源の周波数レジスタの差分へ変換します。
RPN 0の半音・セント指定に対応し、ベンドの時刻は音符分解能への丸め前の
情報を使って60Hzのピッチエンベロープへ変換します。
N106は現在の出力設定（8チャンネル・16サンプル・SA7）を前提にしています。
VRC7は発音中のオクターブブロックを固定してF-numberを変更します。
音源のレジスタ範囲を超えるベンドは範囲内に制限し、警告を表示します。
1フレームの差分は-127～126に制限され、大きな変化は後続フレームへ分割します。
発音期間内に目標値へ到達できない場合や、EPの1020フレームの出力上限を
超える変化がある場合は警告します。広いベンドは完全には再現できません。
計算の確認時は-pt0 -pm128を指定すると、閾値と定義数による省略を減らせます。

MIDIからMMLへの変換には、音源数、同時発音数、音色、音量、ピッチ表現などの
違いによる制約があります。変換後は sample_.mid のトラック構成を確認し、
生成されたMMLをppmckでコンパイルして、実際の演奏結果を確認してください。
